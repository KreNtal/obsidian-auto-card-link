# Domain coverage

Working notes for which sites the fetcher handles, what has been checked, and what
is known to be impossible. Not user documentation — the README covers usage.

Legend: ✅ works · 🟡 works, caveats · ⏳ not yet checked · ❌ unreachable (don't retry)

## Dedicated fetchers

Sites with a handler in `link_metadata_fetcher.ts` (dispatched from `fetchForUrl`).
They answer from an API / oEmbed / JSON endpoint and never read the page HTML, so the
site name comes from `SITE_NAMES`, not `og:site_name`.

The `host` a card shows has a leading `www.` stripped in `fetch()`, once, for every path —
the generic one used to copy whatever the pasted URL happened to say, and the dedicated
fetchers were split roughly half and half between the two forms. Only the leading `www.`
goes: `open.spotify.com`, `en.wikipedia.org` and `clips.twitch.tv` keep their subdomain.
Nothing reads `host` for behaviour, so this is cosmetic; cards already in a vault keep the
form they were written with until refreshed.

`request()` passes `throw: false` to Obsidian's `requestUrl`. Without it requestUrl rejects on every non-2xx, the helper's catch swallows the response, and callers get `undefined` with no status - so until 2026-09-03 a 404 and a dead network were indistinguishable, every `res.status !== 200` test was really only testing `!res`, and the rule below could not fire. `fetchTitleOnly` now also refuses to read a 4xx/5xx page's own `<title>`: it names the error (“404 Not Found”, “Just a moment…”), not the link.

When a page is known not to be readable - a 404 or 410, an auth wall - the **title** comes from the URL (`buildUrlCard`, refined per site by `buildLinkedInFallback`, `buildXFallback`, `buildImdbFallback`), never from the error page, whose `<title>` names the error. Its `og:image` and `og:description` are kept, though: they are the site's own furniture, and Roberto's call (2026-09-03) is that a card carrying the site's graphic reads better than a bare one. Microlink is not asked at all. Once it has answered 429 once, the round trip is skipped for the rest of the session - the quota is daily and per IP, so every further call returns the same 429 - but the notice still fires. Roberto's call: knowing that a link is one the direct fetch cannot handle is worth a notice even on a day when nothing can be done about it, so the skip is about the wasted request, not about the signal. A card is still written either way: the reader gets the link they pasted, in the shape every other link has.

All endpoints re-checked at the network layer on 2026-09-01: each still returns the
fields the code reads. Rendering in Obsidian (image load, layout, downloaded-image
path) is a separate spot-check — see the list at the bottom.

## Generic path — verified

Go through `fetchGeneric` (og/twitter/JSON-LD tags), with the microlink fallback if the
user enabled it. Roberto is verifying these in Obsidian.

`appendSiteName` (markdown links only — a card shows `host` instead) appends the site name unless the title already ends in it after a separator. The recognised set is `-|·•:–—`, so a title like “Some story • Reuters” is left alone; `-` is what gets appended. Verified against the three news sites' real titles on 2026-09-03. One known false negative, contrived enough to leave: the separator split allows zero spaces, so a hyphenated title whose tail happens to equal the site name (“Anti-Trump rally” for a site called “Trump rally”) keeps its suffix off.
